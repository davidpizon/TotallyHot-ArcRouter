## Abstract

> There is a rapidly growing number of large language models (LLMs) that users can query for a fee. We review the cost associated with querying popular LLM APIs—e.g. GPT-4, ChatGPT, J1-Jumbo—and find that these models have heterogeneous pricing structures, with fees that can differ by two orders of magnitude. In particular, using LLMs on large collections of queries and text can be expensive. Motivated by this, we outline and discuss three types of strategies that users can exploit to reduce the inference cost associated with using LLMs: 1) prompt adaptation, 2) LLM approximation, and 3) LLM cascade. As an example, we propose FrugalGPT, a simple yet flexible instantiation of LLM cascade which learns which combinations of LLMs to use for different queries in order to reduce cost and improve accuracy. Our experiments show that FrugalGPT can match the performance of the best individual LLM (e.g. GPT-4) with up to 98% cost reduction or improve the accuracy over GPT-4 by 4% with the same cost. The ideas and findings presented here lay a foundation for using LLMs sustainably and efficiently.

## Method

The problem is to maximize expected answer quality subject to an average cost at most a budget b. A strategy can choose prompts, which APIs to call, and how to combine answers.

Three families:

- **Prompt adaptation.** Shorter prompts cost less. Prompt selection keeps a subset of in-context examples. Query concatenation sends one prompt with several queries so the prompt is not paid repeatedly.
- **LLM approximation.** A completion cache returns a stored answer when a similar query was seen. Model fine-tuning uses a few expensive answers as labels for a cheaper model, which then needs no long prompt.
- **LLM cascade.** Query a list of APIs from cheaper to more expensive. A scorer g(query, answer) in [0, 1] estimates reliability. If the score clears a per-position threshold, return that answer. Otherwise call the next API. The list and the thresholds are a mixed-integer program: average cost within budget, quality of the answer at the stopping position maximized. The paper prunes lists whose answers disagree little, and interpolates the objective from a few samples, instead of solving the integer program directly.

FrugalGPT is the cascade, with length 3. The scorer in the HEADLINES case study is a DistilBERT regression. The cascade needs a first model call before it can score anything, so it is not a pre-routing decision.

Prices were read in March 2023 from 12 APIs across OpenAI, AI21, Cohere, Textsynth, and ForeFrontAI. A bill can be input tokens, output tokens, a fixed fee per request, or a sum of those. The paper's example: 10 million input tokens cost $0.2 on Textsynth GPT-J and $30 on OpenAI GPT-4. Because the schemes differ, the ranking of APIs by cost is not the same on every dataset. J1 charges for generated tokens and not for input tokens; GPT-3 charges for both.

Datasets: HEADLINES (financial-news gold-price direction), OVERRULING (whether a sentence overrules a prior case), and COQA adapted as direct question answering. Each is split into a train set that learns the cascade and a test set.

## Key results

- HEADLINES case study, budget $6.5, one fifth of GPT-4's cost. The learned order is GPT-J, then J1-L, then GPT-4. GPT-J's answer is kept if its score exceeds 0.96; J1-L's if its score exceeds 0.37; otherwise GPT-4 is called. Cost is 80% lower than GPT-4 and accuracy is 1.5% higher.
- Maximum performance improvement: the fraction of items where a cheaper model is right and a more expensive one is wrong. On HEADLINES, GPT-C, GPT-J, and J1-L are each right on about 6% of items where GPT-4 is wrong. On COQA, GPT-3 is right on 13% of items where GPT-4 is wrong.
- Table 3, as described in §4: matching the best individual LLM's performance costs 50% to 98% less. The abstract's matching figure is "up to 98% cost reduction."
- The same section says that at equal cost, accuracy can be up to 5% higher. The abstract says 4% over GPT-4 at the same cost. On OVERRULING, one operating point is +1% accuracy and −73% cost versus GPT-4.
- A remaining failure mode: when every API in the chain gives the same answer, the scorer may still refuse the early ones, and the cascade pays for the whole chain.

The cascade uses a snapshot of 2023 prices inside a budget constraint. It does not describe refreshing those prices, and the scorer sees the query and the generated answer, not the price.
